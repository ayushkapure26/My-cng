# Reusable security requirements for every AI-built project
Copy this file into each project and instruct its coding assistant to implement and verify it. These rules do not automatically propagate to Google AI Studio or other chats/tools.

1. Authentication: use managed authentication or established server hashing libraries. Never store/log passwords. Require verified email, server password policy, expiring access/refresh sessions, logout revocation, single-use expiring reset tokens and account-enumeration protection. Test invalid/expired/replayed tokens, reset links and unverified accounts.
2. Secrets: scan working files and reachable history; redact findings. Privileged DB/service-role/AI keys belong only in server secret storage. Client .env contents bundled into APK/JavaScript are public. Allowlist public configuration. Restrict Maps keys by Android package/signing certificate/API. Rotate exposed credentials; deleting the latest copy does not revoke them.
3. Abuse: enforce login/signup/recovery limits at the auth service. Add atomic per-user and per-IP server quotas, payload/execution limits and HTTP 429 responses to APIs and AI endpoints. Add CAPTCHA/attestation where appropriate and AI spending caps. Client cooldowns are bypassable; never promise total bot/scraping prevention.
4. Deployment: enforce HTTPS and normal TLS verification. Restrict raw DB network access to backend networks where appropriate; protect public Data API access with RLS. Use least privilege, dependency checks and protected stable release signing. Centralize sanitized auth/error/security events with retention and alerts; never log tokens, passwords or personal request bodies. Review device backup and offline-data risks separately.
5. Authorization: derive identity from a verified server session, never request IDs or editable profile metadata. Enforce ownership on every read/write/delete/list and storage/nested object. Test user A, user B, anonymous, expiry, reassignment, batch and concurrent access. Validate payloads, parameterize queries and review all privileged operations that bypass RLS.

Record each control as implemented / verified / blocked / not applicable, with evidence. Do not mark deployment settings complete without checking them. Block production release for unresolved critical controls. Never claim 100% security.
